«Мини-экономика» — Полный гейм-дизайн-документ v2.0
________________________________________
🧭 1. Главная идея
Ребёнок — владелец холдинга в городке Копилкино. Питомец — его партнёр и «лицо» компании (эволюционирует от успехов). Игрок открывает бизнесы, нанимает жителей-ботов, строит цепочки «работа → зарплата → покупка товара → налог → банк». Экономика замкнутая: деньги ботов — это деньги игрока, потому что зарплату платит он же, а боты тратят её в его же магазинах.
Ключевой принцип: каждое действие игрока — это мини-игра. Не «нажал кнопку — магазин открылся», а «прошёл 5 этапов запуска, каждый этап = мини-игра».
________________________________________
🗺 2. Карта районов и их экономика
Город состоит из 6 районов, каждый со своей экономикой. Игрок открывает их по мере роста.
Район	Средняя зарплата	Тип жителей	Что любят покупать	Особенность
Рынок	800 ₡	Торговцы, рабочие	Еда, инструменты	Дешёвый старт, низкая маржа
Спальный	1200 ₡	Семьи, пенсионеры	Продукты, бытовое	Чувствительны к цене
Техно-парк	2500 ₡	IT, инженеры	Гаджеты, кофе, спорт	Любят качество, готовы платить
Центр	3000 ₡	Офисные, менеджеры	Одежда, рестораны, SPA	Высокая аренда, высокая маржа
Промзона	1500 ₡	Рабочие заводов	Инструменты, шиномонтаж	Много рабочих мест
Богатый	5000 ₡	Элита	Люкс, антиквариат	Мало клиентов, огромный чек
Данные для игрока (открываются при исследовании района):
•	📊 Средняя зарплата
•	🏪 Уже существующие магазины (конкуренты) и их цены
•	👥 Численность населения и типы
•	🏗 Свободные участки под застройку
•	🏢 Работодатели (кого можно нанять и куда)
Игрок изучает район мини-игрой «Разведка» — ходит по улицам, снимает данные, сравнивает цены.

🏛 3. Главный Банк — ось всей экономики
Центральный Банк Копилкино (ЦБК) — якорь для всех цен и решений.
Что задаёт ЦБК
•	Ключевая ставка (меняется раз в неделю, от 1% до 15%). Влияет на всё:
o	ставка ↑ → кредиты дорогие, вклады выгодные, люди меньше тратят;
o	ставка ↓ → кредиты дешёвые, люди больше тратят, инфляция растёт.
•	Индекс цен — средняя стоимость «корзины товаров» по городу. Если игрок ставит цены выше индекса на X% — клиенты уходят.
•	Курс ценных бумаг — акции 6 компаний и 3 облигации.
•	Курс валюты «копейка/золотник» — влияет на импортные товары.
Что делает игрок через банк
Действие	Мини-игра	Навык
Открыть вклад	«Подбери срок и процент»	Сложный процент
Взять кредит	«Рассчитай платежи»	Долговая нагрузка
Купить акции	«Биржевой стакан» (реакция)	Риск, диверсификация
Купить облигации	«Собери портфель»	Надёжность vs доходность
Обменять валюту	«Поймай курс»	Курсовые риски
Заплатить налог	«Разложи по конвертам»	Обязательные платежи
Правило: цены в магазинах игрока автоматически подсвечиваются зелёным/жёлтым/красным в зависимости от:
•	среднего индекса ЦБК,
•	средней зарплаты района,
•	цен конкурентов.
________________________________________
🏪 4. Жизненный цикл магазина — 7 этапов, 7 мини-игр
Открывая магазин, игрок проходит путь от пустого помещения до автоматизированной сети.
Этап 1. Выбор района и участка
Мини-игра «Разведка»: пройти по карте, собрать данные о районе (зарплаты, спрос, конкуренты). Чем больше данных — тем точнее прогноз.
Этап 2. Закупка товара
Мини-игра «Найди дешевле»: на экране 3–5 поставщиков с разными ценами, сроками, качеством. Нужно выбрать оптимального. Иногда Сорока-Поставщик обманывает — цена низкая, но товар бракованный.
Игрок должен посчитать:
•	себестоимость единицы,
•	логистику,
•	срок годности,
•	минимальную цену продажи (себестоимость + наценка).
Этап 3. Разгрузка и расстановка
Мини-игра «Полки»: сортировка товара по полкам (по категориям, по сроку, по марже). Ошибся — товар испортился или не нашёлся.
Этап 4. Ценообразование
Мини-игра «Ценник»: для каждого товара выбрать цену. Экран показывает:
•	себестоимость,
•	индекс ЦБК,
•	среднюю зарплату района,
•	цены 3 конкурентов,
•	прогноз спроса (ползунок: цена ↑ → клиентов ↓).
Игрок ставит цену и видит прогноз: «Ожидается 40 покупателей в день». Если ошибся — вечером увидит факт.
Этап 5. Открытие и обслуживание
Мини-игра «Касса»: пока нет сотрудника — игрок сам стоит за кассой. Тап-игра: обслужить клиента, дать сдачу, предложить допродажу. Успел — доход, не успел — клиент ушёл к конкуренту.
Этап 6. Бухгалтерия (обязательно!)
Мини-игра «Журнал»: в конце дня нужно разнести транзакции по категориям. Игрок ведёт полноценный учёт (см. раздел 5).
Этап 7. Найм сотрудников
Когда бизнес стабилен, игрок может нанять ботов на роли. Каждая роль убирает одну мини-игру:
•	Закупщик → автоматизирует Этап 2.
•	Мерчендайзер → Этап 3.
•	Аналитик → подсказывает цены в Этапе 4.
•	Кассир → Этап 5.
•	Бухгалтер → Этап 6.
Но: зарплату платит игрок, и бот может ошибаться. Дешёвый бот = хуже работает.

📒 5. Бухгалтерия — что игрок реально ведёт
Это ядро обучения. Игрок обязан вести пять журналов. Каждый — мини-игра на заполнение.
1. Кассовая книга (приход/расход)
Ежедневно: сколько монет пришло, сколько ушло. Формула: Остаток на конец = Остаток на начало + Приход − Расход.
Мини-игра: перетащить транзакции в колонки «Приход» / «Расход».
2. Товарный журнал (склад)
Товар	Закуплено	Продано	Остаток	Себестоимость
Лимонад	100	78	22	5 ₡
Мини-игра «Инвентаризация»: посчитать остатки на полках и сверить с журналом. Расхождение — воровство или ошибка.
3. Журнал продаж (P&L)
Выручка − Себестоимость = Валовая прибыль.
Валовая прибыль − Зарплаты − Аренда − Налоги = Чистая прибыль.
Мини-игра «Разложи по конвертам»: распределить выручку по конвертам: себестоимость, зарплата, аренда, налог, прибыль.
4. Журнал долгов (кредиты, обязательства)
Кому должен, сколько, когда платить. Просрочка → штраф от ЦБК.
5. Баланс (активы/пассивы)
•	Активы: наличные, товар, здания, акции.
•	Пассивы: кредиты, задолженность по зарплате.
•	Формула: Активы = Пассивы + Капитал.
Мини-игра «Весы»: уравновесить баланс, распределив статьи. Если не сходится — день не закрывается.
Если игрок не ведёт учёт → штрафы, потеря прибыли, падение репутации, грустный питомец.

🤖 6. Мозги ботов (агентная модель)
Каждый житель — автономный агент с потребностями, кошельком и работой.
Структура бота
kotlin
data class Bot(
    val id: Long,
    val district: String,        // где живёт
    val home: String,            // адрес
    val job: Job?,               // где работает
    val salary: Int,             // зарплата
    val wallet: Int,             // наличные
    val savings: Int,            // накопления
    val needs: Needs,            // голод, счастье, усталость
    val preferences: Preferences // что любит, к чему чувствителен
)

data class Needs(
    val hunger: Int,      // 0..100, падает со временем
    val fun: Int,
    val rest: Int,
    val health: Int
)

data class Preferences(
    val priceSensitivity: Float,   // 0.1–2.0 (насколько чувствителен к цене)
    val qualityAffinity: Float,    // предпочитает качество или дешевизну
    val loyalty: Float,            // привязанность к магазину
    val favoriteCategories: List<String>
)
Ежедневный цикл бота
1.	Утро: проснулся → идёт на работу (если есть).
2.	Работа: получает зарплату в конце дня (её платит игрок!).
3.	Вечер: тратит деньги на нужды (еда, досуг, покупки).
4.	Ночь: спит, восстанавливает силы.
Как бот выбирает магазин (алгоритм оценки)
text
score = w1 * (priceScore) +
        w2 * (qualityScore) +
        w3 * (distanceScore) +
        w4 * (loyaltyBonus) +
        w5 * (stockAvailability)

где:
priceScore = max(0, 1 - (цена / (зарплата * priceSensitivity)))
Бот пойдёт в магазин с наивысшим score. Если цена выше его «болевого порога» (например, 15% от зарплаты) — он просто не идёт, а копит или идёт к конкуренту.
Как бот выбирает работу
Ищет вакансию с максимальным (зарплата − стоимость дороги) × комфорт. Если игрок ставит зарплату ниже рынка — никто не придёт. Если выше — придёт больше, чем нужно, но игрок разорится.
Типы ботов
•	Рабочий — низкая зарплата, высокая чувствительность к цене.
•	Инженер — средняя зарплата, ценит качество.
•	Менеджер — высокая зарплата, лоялен к брендам.
•	Пенсионер — фиксированный доход, крайне чувствителен к цене.
•	Студент — мало денег, много свободного времени, любит акции и скидки.
•	Элита — огромная зарплата, безразлична к цене, ищет качество и статус.

🏗 7. Строительство зданий и рынок труда
Игрок может строить не только магазины, но и работодателей:
•	🛞 Шиномонтаж
•	💅 SPA-салон
•	🔧 Ремонт техники
•	🍜 Кафе
•	📚 Курсы
•	🏥 Клиника
Логика трудоустройства
1.	Игрок строит здание (мини-игра «Чертёж» — собрать план из блоков).
2.	Открывает вакансии: указывает должность и зарплату.
3.	Боты района оценивают: устраивает ли их зарплата, далеко ли ехать, комфортно ли.
4.	Бот приходит работать → получает зарплату от игрока → тратит её в магазинах игрока или у конкурентов.
5.	Если игрок ставит слишком низкую зарплату — боты уходят, здание простаивает.
6.	Если слишком высокую — толпа ботов, но расходы съедают прибыль.
Цикл замыкается: игрок платит зарплату → боты тратят у него → он зарабатывает → строит новое здание → нанимает новых ботов. Это и есть живая мини-экономика.

🦝 9. Роль питомца в новой концепции
Питомец теперь — аватар бизнеса:
•	Его уровень = репутация холдинга.
•	Его настроение = тонус команды: если грустит, боты работают хуже.
•	Его внешний вид = бренд: можно кастомизировать под район (в Техно-парке — строгий костюм, на Рынке — фартук).
•	Питомец ходит в районы вместе с игроком в мини-игре «Разведка» и реагирует на события.
Эволюция питомца теперь привязана к бизнес-достижениям:
•	Открыл 1 магазин → подросток.
•	Открыл 5 → взрослый.
•	Построил 10 зданий и нанял 50 ботов → «магнат».

🧠 10. Логика влияния игрока на район
Игрок может менять экономику района:
•	Строить работодателей → повышать среднюю зарплату → боты богатеют → больше тратят.
•	Строить магазины → увеличивать конкуренцию → цены падают.
•	Поднимать цены → боты уходят, район беднеет.
•	Открывать SPA и кафе → растёт «счастье» ботов → они лояльнее и тратят больше.
•	Инвестировать в благоустройство → привлекать элиту → рост цен на недвижимость.
Динамическая экономика: каждый день район пересчитывает:
•	среднюю зарплату,
•	индекс цен,
•	спрос,
•	уровень счастья.
Если игрок ведёт район к процветанию — питомец растёт быстрее. Если к упадку — боты уезжают, магазины закрываются.

🛠 11. Технические заметки (без внешних сервисов)
•	Всё локально: Room + DataStore + WorkManager.
•	Симуляция ботов — раз в игровой день через WorkManager, батчами, чтобы не грузить CPU.
•	Экономический движок — чистый Kotlin-модуль domain/economy с тестами.
•	ML on-device (TFLite): адаптация сложности мини-игр и прогноз спроса для подсказок.
•	Рендер карты — Jetpack Compose Canvas или игровой движок на Compose.
•	Сохранение состояния — автосейв после каждого действия в Room, чтобы не потерять прогресс.
•	Экспорт отчёта родителю — PDF через Android API.

🎯 12. Уникальность обновлённой концепции
1.	Мини-игры = механики бизнеса. Нет отдельного «режима игры» — всё вплетено.
2.	Живая агентная экономика. Боты — не декорации, а настоящие участники рынка.
3.	Игрок сам формирует рынок труда и цены. Можно разорить район или поднять его.
4.	Полноценный учёт. Ребёнок ведёт кассу, склад, P&L, баланс — как настоящий предприниматель.
5.	Главный банк как ось. Все цены, ставки, акции — из одного источника.
6.	Автоматизация через найм. Ребёнок учится делегировать, понимая, что сотрудники стоят денег.
7.	Офлайн и без сбора данных. Полностью безопасно для ребёнка.

«Мини-экономика» — Математическая модель, движок и баланс
Ниже — три технических документа, готовых к переносу в код на Kotlin.

🧠 Часть 1. Математическая модель бота
1.1. Структура бота (модель данных)
kotlin
data class Bot(
    val id: Long,
    val type: BotType,
    val districtHome: String,
    val workDistrict: String?,      // null = безработный
    val employerId: Long?,          // id здания, где работает
    val salary: Int,                // ₡/день, назначает игрок
    val wallet: Int,                // наличные на руках
    val savings: Int,               // накопления (в ЦБК)
    val age: Int,
    val needs: Needs,
    val prefs: Preferences,
    val loyalty: MutableMap<Long, Double>, // shopId -> 0..1
    val mood: Double,               // 0..1
    val unemployedDays: Int
)

data class Needs(
    val hunger: Double,     // 1.0 = сыт, падает на 0.15/день
    val fun: Double,        // падает на 0.10/день
    val rest: Double,       // падает на 0.20/день
    val health: Double      // падает, если другие < 0.2
)

data class Preferences(
    val priceSensitivity: Double,   // 0.2 .. 1.5
    val qualityAffinity: Double,    // 0.1 .. 1.0
    val loyaltyRate: Double,        // 0.02 .. 0.15 (насколько быстро привязывается)
    val favoriteCategories: List<Category>,
    val maxFoodShareOfIncome: Double // доля дохода на еду, 0.05..0.30
)
1.2. Ключевые формулы
1.2.1. Платёжеспособность (Willingness To Pay, WTP)
Бот готов платить за товар p не больше, чем его «ощутимая» цена, зависящая от дохода:

text
WTP(bot, p) = basePrice(p) × (bot.income / REF_INCOME) ^ 0.7
REF_INCOME = 1500 ₡ — средний класс.

Показатель 0.7 — эмпирический: спрос растёт медленнее дохода (закон Энгеля).

Пример: если лимонад в базе стоит 8 ₡, а бот зарабатывает 800 ₡/день:
WTP = 8 × (800/1500)^0.7 = 8 × 0.60 = 4.8 ₡ → бедный бот не купит по 8 ₡.

1.2.2. Оценка магазина (shop score)
Для каждого магазина s, продающего товар p, бот считает:

text
score(s, p) = w_price    × priceScore
            + w_quality  × qualityScore
            + w_distance × distanceScore
            + w_loyalty  × loyaltyScore
            + w_stock    × stockScore
            + w_brand    × brandScore
priceScore:

text
priceScore = clamp(1 − bot.prefs.priceSensitivity × (price(s,p) / WTP(bot,p) − 1), 0, 1)
Если цена = WTP → 1.0. Если в 2 раза выше WTP и sensitivity=0.5 → 0.5.

qualityScore:

text
qualityScore = shop.quality × bot.prefs.qualityAffinity
shop.quality ∈ [0,1] — зависит от апгрейдов здания.

distanceScore:

text
distanceScore = clamp(1 − distance(bot.home, shop) / MAX_DIST, 0, 1)
MAX_DIST = 5.0  // км в игре
loyaltyScore:

text
loyaltyScore = bot.loyalty[shop.id] ?: 0.0

1.2.4. Решение о покупке

fun decidePurchase(bot: Bot, product: Product, shops: List<Shop>): Shop? {
    val candidates = shops
        .filter { it.hasProduct(product) }
        .map { it to shopScore(bot, it, product) }
        .filter { (_, score) -> score >= PURCHASE_THRESHOLD }  // 0.30
        .sortedByDescending { it.second }

    val best = candidates.firstOrNull() ?: return null

    // Проверка бюджета
    val budget = bot.wallet + bot.savings * 0.2   // тратит не более 20% накоплений
    if (best.first.price(product) > budget) return null

    return best.first
}
1.2.5. Оценка работы (job score)
Для каждой вакансии v:

text
jobScore(bot, v) = w_s × salaryScore(v)
                 + w_d × distScore(bot, v)
                 + w_c × comfortScore(v)
                 + w_r × reputationScore(v.employer)
salaryScore:

text
salaryScore = clamp((v.salary − marketAvgSalary) / marketAvgSalary + 1, 0, 2) / 2
Зарплата = рынок → 0.5

В 2 раза выше рынка → 1.0

В 2 раза ниже рынка → 0.0

comfortScore — условия труда: v.employer.amenities / 10.0 (0..1).

reputationScore — репутация работодателя (0..1), падает при задержках зарплаты.

Веса: w_s = 0.55, w_d = 0.15, w_c = 0.15, w_r = 0.15

1.2.6. Правила приёма и увольнения
Бот соглашается на работу, если:

text
jobScore ≥ 0.40  AND  v.salary ≥ bot.minAcceptableSalary
где minAcceptableSalary = districtAvgSalary × (1 − bot.prefs.priceSensitivity × 0.3).

Бот увольняется, если:

Зарплата ниже порога 3 дня подряд;

Репутация работодателя < 0.3;

Нашёл работу со score выше текущей на 0.20+.

1.2.7. Обновление потребностей (в конце дня)
text
hunger  = clamp(hunger  − 0.15 + foodPurchased × 0.5, 0, 1)
fun     = clamp(fun     − 0.10 + funPurchased  × 0.5, 0, 1)
rest    = clamp(rest    − 0.20 + slept          × 0.7, 0, 1)

если (hunger < 0.2 || fun < 0.2) → health -= 0.1
иначе → health += 0.05

mood = (hunger + fun + rest + health) / 4
1.2.8. Распределение дохода
kotlin
fun distributeIncome(bot: Bot) {
    val income = bot.salary
    val tax = (income * TAX_RATE).toInt()          // TAX_RATE = 0.13
    val net = income - tax
    val essentials = (net * 0.50).toInt()
    val wants      = (net * 0.20).toInt()
    val savings    = (net * 0.20).toInt()
    val buffer     = net - essentials - wants - savings

    bot.wallet += essentials + wants
    bot.savings += savings
    bot.wallet += buffer
}

fun updateEmployment(district: DistrictState) {
    // Увольнения
    for (bot in district.bots) {
        val emp = bot.employerId?.let { district.employers.find(it) } ?: continue
        if (bot.salary < bot.minAcceptableSalary() && bot.unemployedDays < 3) {
            bot.unemployedDays++
        } else if (bot.salary < bot.minAcceptableSalary()) {
            emp.fire(bot)
            bot.employerId = null
            bot.salary = 0
        }
    }

    // Приём на работу
    val vacancies = district.employers.flatMap { it.openVacancies() }
    val unemployed = district.bots.filter { it.employerId == null }
        .sortedByDescending { it.needs.hunger }   // самые голодные ищут работу первыми

    for (bot in unemployed) {
        val best = vacancies
            .map { it to jobScore(bot, it) }
            .filter { (_, s) -> s >= 0.40 }
            .maxByOrNull { it.second }
            ?.first ?: continue

        best.hire(bot)
        bot.salary = best.salary
        bot.employerId = best.id
        bot.unemployedDays = 0
    }
}
Шаг 2 — Выплата зарплат

fun paySalaries(district: DistrictState) {
    for (emp in district.employers) {
        val payroll = emp.employees.sumOf { it.salary }
        if (emp.cash >= payroll) {
            emp.cash -= payroll
            emp.reputation = min(1.0, emp.reputation + 0.02)
            emp.employees.forEach { it.wallet += (it.salary * 0.87).toInt() } // минус налог
        } else {
            emp.reputation = max(0.0, emp.reputation - 0.15)
            // Частичная выплата + возможные увольнения
        }
    }
}
Шаг 3 — Расходы ботов
kotlin
fun simulateBotSpending(district: DistrictState) {
    for (bot in district.bots) {
        val neededProducts = bot.decideShoppingList()   // на основе needs
        for (product in neededProducts) {
            val shop = decidePurchase(bot, product, district.shops) ?: continue
            val price = shop.price(product)

            if (bot.wallet >= price) {
                bot.wallet -= price
                shop.cash += price
                shop.soldToday[product] = shop.soldToday.getOrDefault(product, 0) + 1
                shop.stock[product] = shop.stock.getOrDefault(product, 0) - 1

                bot.needs = bot.needs.consume(product)
                bot.loyalty[shop.id] = min(1.0,
                    (bot.loyalty[shop.id] ?: 0.0) + bot.prefs.loyaltyRate)
            }
        }
    }
}
Шаг 4 — Пересчёт магазинов
kotlin
fun updateShops(district: DistrictState) {
    for (shop in district.shops) {
        val revenue = shop.soldToday.values.sumOf { it * shop.avgPrice() }
        val goodsCost = shop.soldToday.entries.sumOf { (p, qty) ->
            qty * shop.costPrice(p)
        }
        val payroll = shop.employees.sumOf { it.salary }
        val rent = shop.districtRent
        val tax = (revenue * TAX_RATE).toInt()

        shop.profitToday = revenue - goodsCost - payroll - rent - tax
        shop.cash += shop.profitToday

        // Репутация магазина растёт, если много покупателей и всё в наличии
        val lostCustomers = shop.visitorsToday - shop.soldToday.values.sum()
        shop.brandLevel = clamp(
            shop.brandLevel + 0.05 * shop.soldToday.values.sum() - 0.10 * lostCustomers,
            0.0, 10.0
        )
    }
}

fun updateDistrictAggregates(district: DistrictState) {
    val employed = district.bots.filter { it.employerId != null }
    district.employed = employed.size
    district.avgSalary = if (employed.isEmpty()) 0.0
                         else employed.map { it.salary }.average()
    district.avgIncome = district.bots.map { it.salary + pension(it) }.average()
    district.happiness = district.bots.map { it.mood }.average()

    district.priceIndex = computeBasketPrice(district.shops)
    district.demandIndex = district.bots.sumOf { it.dailyDemand() }
    district.supplyIndex = district.shops.sumOf { it.stockTotal() }
}
Шаг 6 — Обновление ЦБК
kotlin
fun updateCentralBank(cbk: CentralBankState, district: DistrictState) {
    val inflation = (district.priceIndex - cbk.prevPriceIndex) / cbk.prevPriceIndex
    val unemployment = 1.0 - district.employed.toDouble() / district.workingAge
    val growth = (district.demandIndex - cbk.prevDemand) / cbk.prevDemand

    cbk.keyRate = clamp(
        cbk.baseRate + 0.5 * inflation - 0.3 * unemployment + 0.2 * growth,
        0.01, 0.15
    )

    cbk.prevPriceIndex = district.priceIndex
    cbk.prevDemand = district.demandIndex

    // Ставка по вкладам и кредитам
    cbk.depositRate = cbk.keyRate * 0.8
    cbk.loanRate = cbk.keyRate + 0.05
}
Шаг 7 — Дрейф цен конкурентов
kotlin
fun driftCompetitorPrices(district: DistrictState, cbk: CentralBankState) {
    val pressure = clamp(
        (district.demandIndex - district.supplyIndex) / max(1.0, district.supplyIndex),
        -0.2, 0.2
    )
    for (shop in district.shops.filter { it.isCompetitor }) {
        for (product in shop.products) {
            val newPrice = shop.price(product) *
                (1 + cbk.inflationRate) *
                (1 + pressure)
            shop.setPrice(product, newPrice)
        }
    }
}

Действие игрока	Формула влияния
